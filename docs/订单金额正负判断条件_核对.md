# 订单金额正负判断条件 核对报告

|----------|------|---------------------|----------|
| **订单** | 订单金额_外币/本币 | ❌ 否 | `sales_three_match.py` 175-178、`three_lists.py` 257-260 |

## 二、订单金额逻辑（当前）

```python
# sales_three_match.py 175-178
# three_lists.py 257-260
# 订单金额与数量不再按 SHKZG/RETPO 或发票类型取负，仅用原始数值
df_order['订单金额_外币'] = df_order['NETWR'].fillna(0)
df_order['订单金额_本币'] = df_order['订单金额_外币'] * wkurs
```

- **订单金额**：直接使用 VBAP.NETWR，不做 SHKZG/RETPO 符号调整
- **订单数量**：KLMENG 或 KWMENG×UMVKZ/UMVKN，同样不做符号调整

---

## 三、发票/交货的 SHKZG 逻辑（对比）

```python
# SHKZG 映射（发票、交货一致）
shkzg_map = shkzg_upper.map({'S': 1, 'H': -1, 'X': -1}).fillna(1)
# S=借方(正), H=贷方(负), X=冲账/负值
```

- **发票金额**：`NETWR × shkzg_map`
- **发票数量**：`FKIMG × shkzg_map`（three_lists 用 FKIMG；sales_three_match 用 FKLMG/FKIMG 换算）
- **交货数量**：`LFIMG × shkzg_map`

---

## 四、VBAP 字段说明（config.py）

- **NETWR**：行净价值
- **SHKZG**：借贷标识（S=借方，H=贷方）
- **RETPO**：退货标识（X=退货行）

VBAP 与 VBRP/LIPS 一样有 SHKZG，但当前订单金额**未使用** VBAP.SHKZG。

## 六、结论与建议

### 当前设计

- 订单金额、数量：**不做** SHKZG/RETPO 取负，使用原始 NETWR/KLMENG
- 发票、交货：**按** SHKZG 取正负

### 可能原因

1. 假设 VBAP.NETWR 在 SAP 中已带正确符号（退货时 NETWR 为负）
2. 或之前「去掉订单金额、数量的取负逻辑」的修改，有意简化订单侧处理

### 若需与发票一致

若业务要求订单金额与发票金额在符号上一致（如退货订单金额应为负），可考虑：

1. 在 VBAP 有 SHKZG 时，对订单金额应用与发票相同的映射：
   ```python
   if 'SHKZG' in df_order.columns:
       shkzg_map = df_order['SHKZG'].fillna('S').str.upper().map({'S': 1, 'H': -1, 'X': -1}).fillna(1)
   else:
       shkzg_map = 1
   df_order['订单金额_外币'] = df_order['NETWR'].fillna(0) * shkzg_map
   ```
2. 或结合 RETPO：RETPO='X' 时对金额取负（取决于客户 SAP 配置）

### 建议

- 先确认客户 SAP 中 VBAP.NETWR 的存储方式（是否已带符号）
- 若 NETWR 恒为正、靠 SHKZG/RETPO 表示负，则应在订单金额中引入 SHKZG/RETPO 逻辑
- 若 NETWR 已带符号，则当前实现合理，仅需更新文档
